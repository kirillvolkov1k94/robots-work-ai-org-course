# Scope lock — «Роботы работают»

## In scope

- Публичный учебный материал и Agent Org Blueprint v1 для одного ограниченного процесса.
- Studio Intelligence Brief только как read-only/draft-only pattern: публичные или заранее подготовленные входы, внутренний черновик, QA, внутренний отчёт либо APPROVAL_REQUEST.
- Хранение в приложении только метаданных прохождения: course ID, lesson ID, score и timestamps.

## Data and access policy

- Learner artifacts живут в личных заметках вне приложения; курс не собирает свободный текст.
- Не вводить и не хранить клиентскую переписку, номера телефонов, API keys, пароли, контракты или секреты.
- У курса и примера нет service-role policy: service-role key, база, admin token и production-write доступы не нужны и запрещены.
- Удаление данных, внешняя публикация, клиентское сообщение, реклама, CRM, запись, платёж и изменение сайта требуют отдельного одобрения владельца и не являются упражнением.

## Hard stops

- При нехватке данных — `MISSING_DATA`; при противоречии или неясном риске — `REVIEW_REQUIRED`.
- При внешнем действии — `APPROVAL_REQUEST` до действия.
- Тесты, логи и метаданные не доказывают живую активацию или бизнес-результат.

## Acceptance boundary

Desktop/emulator-проверка не заменяет физическое принятие на iPhone: Home Screen install, Safari и реальный пользовательский путь принимает человек отдельно.
